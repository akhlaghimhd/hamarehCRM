## ۰. حاکمیت و گردش کار عامل

### ۰.۱ اولویت مطلق قوانین
قوانین این فایل و اسناد مرجع مخزن نادیده گرفته نمی‌شوند. هر تناقض فوراً به کاربر گزارش شود.

### ۰.۲ منبع حقیقت = گیت
وضعیت واقعی کد، اسکیما و ساختار فقط از مخزن `akhlaghimhd/hamarehCRM` خوانده می‌شود. حدس، حافظه قدیمی یا artifacts به‌جای خواندن گیت ممنوع است.

### ۰.۳ خواندن قبل از ویرایش
قبل از هر تغییر، فایل فعلی از گیت خوانده شود. کار بر اساس فرض ممنوع است.

### ۰.۴ گردش کار استاندارد
1. خواندن زمینه + فایل‌های مرتبط از گیت  
2. اعمال تغییر مستقیم روی مخزن (کانکتور GitHub) روی برنچ `develop` مگر خلاف آن گفته شود  
3. کامیت با پیام **انگلیسی** معنادار (conventional: `feat:`, `fix:`, `chore:`, `docs:`)  
4. گزارش کوتاه فارسی: لیست فایل‌های ایجاد/ویرایش‌شده  
5. دادن دستور به‌روزرسانی لوکال به کاربر:  
   ```bash
   git fetch origin
   git pull origin develop
   git log ORIG_HEAD..HEAD --oneline
   git diff --name-status ORIG_HEAD..HEAD
   ```
6. در صورت تغییر منطق کسب‌وکار: مسیر تست مرتبط + درخواست تأیید سبز شدن از کاربر  
7. در اصلاح بعد از تست: ساده‌سازی یا پاک کردن صورت‌مسئله ممنوع؛ توضیح کوتاه خطا + اقدام مطابق همین قوانین

### ۰.۵ محدوده تغییر
- فقط فایل/موضوع درخواست‌شده تغییر کند.
- فایل هم‌مسیر یا «بهبود جانبی» بدون درخواست اضافه نشود.
- بازنویسی کامل Resource/صفحه لیست فقط با اجازه صریح کاربر.

### ۰.۶ زبان
- پیام Commit: انگلیسی  
- گزارش و توضیح برای کاربر: فارسی

## GIT. قوانین گیت (قفل‌شده)

**G1. شاخه‌ها**
- `main` = پایدار و تأییدشده (در صورت وجود)
- `develop` = کار روزانه — پیش‌فرض Push و کار عامل
- مستقیم روی `main` نوشته نشود مگر دستور صریح کاربر

**G2. نوشتن روی remote**
- تغییرات کد از طریق کانکتور GitHub روی همین مخزن انجام شود.
- Force push فقط با دستور صریح کاربر

**G3. پس از هر کامیت remote**
همیشه دستورهای بند ۰.۴-۵ به کاربر داده شود.

**G4. فایل تست دسترسی**
فایل‌های موقت مثل `grok-access-test.txt` بعد از تأیید دسترسی پاک شوند و در مخزن نمانند.
