# استاندارد طراحی صفحات پنل — hamarehCRM / myoffice

**نسخه:** 1.0.0  
**تاریخ:** 2026-11-14  
**استک:** Laravel 13 + Filament 4 + RTL + Vazirmatn + `App\Support\Fa`  
**مکمل اجباری:** `TABLE_STANDARDS.md` ، `AGENT_RULES.md` بخش UI

هدف: هر صفحهٔ جدید (لیست، فرم، مشاهده/میزکار، صفحهٔ سفارشی) بدون «طراحی از صفر» ساخته شود و تجربهٔ کاربر یکدست بماند.

قبل از merge هر صفحه، چک‌لیست انتهای این سند تیک بخورد.

---

## ۰. اصول کلی (غیرقابل‌چانه)

| # | اصل | توضیح |
|---|-----|--------|
| P1 | **فارسی + RTL** | همه برچسب‌ها، پیام‌ها، empty state، تأییدها فارسی. `dir=rtl` از پنل. |
| P2 | **اعداد فارسی** | نمایش از `Fa::digits` / `Fa::number` / `Fa::dateTime`؛ نه `strtr` پراکنده. |
| P3 | **چندشرکتی** | Query بدون `company_id` / اسکوپ شرکت ممنوع. |
| P4 | **عدم دسترسی = Notification** | نه 404 خام برای اکشن غیرمجاز. |
| P5 | **یک مسیر بصری** | Resource جدا CSS ننویسد مگر استثنا + تأیید. استایل سراسری: `filament-fa.css` / theme. |
| P6 | **تمرکز بر کار** | صفحهٔ عملیاتی (مثل میزکار فرصت) فرم کامل را جلو نیندازد؛ ویرایش دادهٔ پایه ثانویه است. |
| P7 | **Filament بومی** | اول قابلیت‌های Filament 4؛ UI سفارشی فقط وقتی الگوی استاندارد پوشش ندهد. |

## ۱. انواع صفحه و اسکلت اجباری

### ۱.۱ لیست (`ListRecords`)

| عنصر | الزام |
|------|--------|
| عنوان صفحه | از `$navigationLabel` / `getTitle()` — کوتاه و کاری (مثلاً «فرصت‌ها») |
| آیکن ناوبری | `protected static string\|BackedEnum\|null $navigationIcon` — Heroicon outline یکدست در گروه |
| گروه منو | `navigationGroup` مطابق گروه‌های پنل (بازاریابی / فروش / …) |
| دکمهٔ اصلی هدر | معمولاً «ایجاد …» (`CreateAction`) — primary |
| اکشن ثانویه هدر | حداکثر ۲–۳ مورد پرکاربرد (مثلاً ثبت سریع)؛ بقیه در منو |
| جدول | طبق `TABLE_STANDARDS.md` کامل |
| Empty state | heading + description + action ایجاد |
| فیلتر | پیش‌فرض dropdown (قیف)؛ نه نوار شلوغ بالای جدول مگر تصمیم قطعی |

### ۱.۲ ایجاد / ویرایش (`CreateRecord` / `EditRecord`)

| عنصر | الزام |
|------|--------|
| عنوان | «ایجاد …» / «ویرایش …» یا نام رکورد در edit |
| Breadcrumb | فعال (Resource → لیست → این صفحه) |
| بخش‌بندی فرم | `Section` با عنوان شماره‌دار یا موضوعی؛ اختیاری‌ها `collapsed()` |
| عرض فیلد | موبایل ۱ ستون؛ md+ ۲–۳ ستون منطقی؛ از ستون باریک بلند اجتناب |
| دکمهٔ ثبت | هدر و/یا پایین؛ «ثبت و جدید» فقط اگر سناریو تکرار زیاد دارد |
| Validation | پیام فارسی روی همهٔ ruleهای کاربرمحور |
| Redirect بعد از create | به صفحهٔ **کار بعدی** (مثلاً میزکار)، نه لزوماً edit خام |
| Helper زیر فیلد | فقط وقتی ابهام واقعی است؛ متن بلند ممنوع (فرم را دراز نکن) |

### ۱.۳ مشاهده / میزکار (`ViewRecord` یا صفحهٔ سفارشی عملیاتی)

| عنصر | الزام |
|------|--------|
| عنوان | نام موجودیت کسب‌وکار (سازمان / عنوان فرصت)، نه «View» |
| نوار وضعیت | کد، وضعیت، مرحله، مهلت — فشرده بالای محتوا |
| ستون اصلی | همان کاری که کاربر برایش آمده (گام، فعالیت، سفارش، …) |
| سایدبار / کارت خلاصه | مخاطب، مالک، محصول، متادیتای فقط‌خواندنی |
| اکشن هدر | ویرایش اطلاعات، ارجاع، حذف — secondary/danger واضح |
| اکشن داخل کارت | ثبت فعالیت، بستن گام، … نزدیک به همان بخش |
| Action در Blade | `{{ $this->actionName }}` **بدون** `()` ؛ + `<x-filament-actions::modals />` |

### ۱.۴ صفحهٔ سفارشی (گزارش، قیف، تنظیمات)

| عنصر | الزام |
|------|--------|
| `getTitle()` / `getHeading()` | اجباری و فارسی |
| آیکن ناوبری | اجباری اگر در منو است |
| `canAccess()` | اگر محدود به نقش است |
| هدر اکشن | از `getHeaderActions()` نه دکمهٔ HTML خام پراکنده |
| Empty / خطا | پیام راهنما + مسیر بعدی |

## ۲. هدر صفحه (Header)

الگوی ثابت از بالا به پایین (RTL):

1. **Breadcrumb** (مسیر بازگشت) — مگر صفحهٔ ریشهٔ داشبورد  
2. **عنوان** (+ در صورت نیاز زیرعنوان یک خطی)  
3. **اکشن‌های هدر** — هم‌تراز با عنوان؛ روی موبایل فشرده / منو

### ۲.۱ قوانین اکشن هدر

| اولویت | نقش | رنگ / ظاهر |
|--------|-----|------------|
| ۱ | عمل اصلی مثبت (ایجاد، ثبت) | `primary` / دکمهٔ پر |
| ۲ | عمل پرکاربرد خنثی (ارجاع، ویرایش اطلاعات) | `gray` / outline |
| ۳ | خطر (حذف) | `danger` + تأیید |
| — | بیش از ۳ دکمهٔ همیشه نمایان | بقیه را در `ActionGroup` بگذار |

- برچسب کوتاه فارسی + آیکن Heroicon در صورت ابهام  
- اکشن مخرب: `requiresConfirmation()` + متن نتیجه  
- لینک خارجی / صفحهٔ دیگر: `->url(...)` نه action خالی بدون بازخورد  

### ۲.۲ عنوان و آیکن

- عنوان: کار کاربر («فرصت‌ها»، «میزکار فرصت») نه اصطلاح فنی انگلیسی  
- آیکن منو با بقیهٔ گروه یک خانواده (outline)  
- از عنوان‌های تکراری با breadcrumb خودداری (breadcrumb = مسیر، heading = الان کجایی)

---

## ۳. Breadcrumb

- برای Resource استاندارد Filament: فعال بماند  
- زنجیرهٔ منطقی: **گروه یا ماژول ← لیست ← رکورد / عمل**  
- در صفحات عمیق (گام داخل فرصت): فرصت در مسیر باشد تا یک کلیک تا میزکار  
- از breadcrumb برای دکمهٔ «بازگشت» پنهان استفاده نکن؛ اگر نیاز به بازگشت قوی است دکمهٔ هدر هم بگذار  

---

## ۴. جدول (خلاصه — جزئیات در TABLE_STANDARDS)

حداقلی که صفحهٔ لیست بدون آن رد نمی‌شود:

1. `recordUrl` آگاهانه (null یا مسیر میزکار/view — نه edit خام تصادفی)  
2. ویرایش/ورود از لینک نام یا اکشن صریح  
3. ستون وضعیت با badge یا Icon + تأیید برای تغییر  
4. فیلتر dropdown پیش‌فرض  
5. `defaultSort` مشخص  
6. pagination `[10, 15, 25, 50, 100]` بدون کلید فارسی  
7. empty state کامل با Create  
8. soft delete: TrashedFilter + Restore در صورت مدل soft-delete  
9. ستون‌های فرعی `toggleable(isToggledHiddenByDefault: true)`  
10. مبلغ/تاریخ با `Fa`  

پیشنهادی Filament 4 (در صورت نیاز واقعی، نه تزئین):

- `reorderableColumns()` برای لیست‌های پستون  
- `stackedOnMobile()` اگر جدول روی موبایل غیرقابل‌استفاده است

## ۵. باکس / کارت / Section

| الگو | کاربرد | قانون |
|------|--------|--------|
| **Section فرم** | گروه‌بندی فیلد | عنوان واضح؛ اختیاری‌ها collapsed؛ بدون helper رمان‌گونه |
| **کارت خلاصه** | فقط‌خواندنی کنار میزکار | برچسب کوچک + مقدار؛ فاصلهٔ یکدست؛ خالی = «—» |
| **کارت کار** | گام جاری، وظیفه | عنوان کار + اکشن‌های همان کارت + لیست زیرمجموعه |
| **نوار وضعیت (status bar)** | کد/وضعیت/مهلت | pillهای کوتاه؛ خطر (عقب‌افتاده) متمایز |
| **Empty dashed** | لیست خالی داخل کارت | یک جمله + اشاره به دکمهٔ همان بخش |

CSS سفارشی صفحه فقط با کلاس‌های پیشونددار (مثل `opp-workspace`) و فایل CSS اختصاصی یا `filament-fa.css` — نه Tailwind purge‌شوندهٔ تصادفی در Blade بدون theme source.

## ۶. فرم

1. ترتیب فیلد = ترتیب فکر کاربر (شناسایی ← تماس ← نیاز ← مرحله ← گام)  
2. اجباری‌ها در بخش‌های باز؛ پیشرفته/یادداشت collapsed  
3. موبایل: تک‌ستون؛ دسکتاپ: Grid صریح برای ردیف‌های جفت (نه ستون باریک یتیم)  
4. تاریخ: شمسی (`jalali` وقتی پکیج لود است)  
5. تلفن: استاندارد ۱۱ رقم ایران در validation  
6. سقف `maxLength` روی متن‌های آزاد  
7. پیام موفقیت بعد از ثبت: مثبت، کوتاه، با هدایت به مرحلهٔ بعد

## ۷. بازخورد و حالت‌ها

| حالت | رفتار |
|------|--------|
| موفق | Notification فارسی + در صورت نیاز redirect |
| خطا validation | زیر فیلد / خلاصهٔ فارسی؛ نه متن خام انگلیسی Laravel |
| خالی | empty state راهنما |
| بارگذاری | همان skeleton/spinner Filament |
| بدون مجوز | Notification؛ مخفی کردن اکشن با `visible`/`authorize` |

## ۸. موبایل و چگالی

- هدر اکشن‌ها روی موبایل جمع‌شونده یا تمام‌عرض منظم  
- جدول: اسکرول افقی یا `stackedOnMobile` — تصمیم یکسان در ماژول  
- کارت‌های میزکار: زیر هم روی `< lg` ؛ دو ستون از `lg` به بالا  
- حداقل اندازهٔ لمسی دکمه‌ها رعایت شود (دکمهٔ خطر جدا از دکمهٔ اصلی)

## ۹. ناوبری و IA

- هر Resource در **یک** گروه منو  
- برچسب منو = همان زبان کاربر کسب‌وکار  
- صفحات «عمیق استخر داده» اگر روزمره نیستند از منوی اصلی پنهان (`shouldRegisterNavigation`)  
- مسیر بعد از create/edit از پیش در سند ماژول مشخص شود

## ۱۲. مرجع سریع Filament 4 (هم‌راستا با این استاندارد)

- Header actions: `getHeaderActions()` روی صفحه  
- Empty state جدول: `emptyStateHeading` / `Description` / `Actions` / `Icon`  
- جدول واکنش‌گرا: `stackedOnMobile()` در صورت نیاز  
- ستون‌ها: `toggleable`, در صورت نیاز `reorderableColumns()`  
- Action یکپارچه: `Filament\Actions\Action`
