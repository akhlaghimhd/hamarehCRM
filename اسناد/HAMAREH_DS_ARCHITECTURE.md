# معماری طراحی hamareh-ds

## وضعیت
تصمیم‌های مالک درباره پوسته چندشرکتی و تنظیمات ظاهری شرکت مبنای پیاده‌سازی است.

## اصول
- Design System مرکزی و مشترک است؛ شرکت‌ها نسخه جداگانه CSS یا صفحه اختصاصی ندارند.
- هر شرکت می‌تواند پالت آماده یا رنگ دلخواه داشته باشد.
- رنگ اصلی و رنگ ثانویه در سطح شرکت قابل انتخاب‌اند.
- تراکم رابط کاربری در سطح شرکت تنظیم می‌شود.
- تنظیمات ظاهری با company_id و از طریق CompanySettings ذخیره می‌شوند؛ جدول یا سیستم تنظیمات موازی ایجاد نمی‌شود.
- نبود Company Context معتبر فقط به پوسته پیش‌فرض هم‌ره منتهی می‌شود و هرگز باعث خواندن تنظیمات شرکت دیگری نمی‌شود.

## مدل داده
کلید رزروشده تنظیمات: ui.theme از نوع json
- palette: یکی از پالت‌های آماده یا custom
- primary: رنگ HEX شش‌رقمی
- secondary: رنگ HEX شش‌رقمی
- density: یکی از compact، balanced یا comfortable

مقادیر پیش‌فرض در صورت نبود تنظیم:
- پالت هم‌ره
- رنگ اصلی #087E78
- رنگ ثانویه #3976B8
- تراکم balanced

## پالت‌های اولیه
- هم‌ره
- اقیانوس
- جنگل
- بنفش
- گرافیتی
- رنگ دلخواه

این فهرست داده پیش‌فرض Design System است و می‌تواند در نسخه‌های بعدی توسعه یابد.

## اعمال در رابط
- FilamentColor پالت‌های primary و secondary را در زمان رندر بر اساس Company Context ثبت می‌کند.
- CSS مرکزی hamareh-ui-v2.css از توکن‌های --hm-company-primary و --hm-company-secondary استفاده می‌کند.
- تراکم از طریق data-hm-density و توکن‌های مرکزی جدول، فرم و کنترل اعمال می‌شود.
- رنگ ورودی فقط HEX شش‌رقمی پذیرفته می‌شود؛ CSS خام یا style سفارشی از کاربر دریافت نمی‌شود.
- تغییر پوسته پس از ذخیره و بارگذاری مجدد پنل اعمال می‌شود.

## امنیت و تست
- مدیریت پوسته فقط برای مدیر همان شرکت مجاز است.
- تنظیمات از Company Context جاری خوانده و نوشته می‌شوند.
- تست جداسازی پوسته دو شرکت، اعتبار رنگ، سطح دسترسی و تراکم الزامی است.
- CSSهای تولیدشده Filament در public منبع طراحی نیستند و دستی تغییر نمی‌کنند.
