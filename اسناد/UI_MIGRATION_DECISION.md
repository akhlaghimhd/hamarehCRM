## زمینه و تصمیم

مالک پروژه در تاریخ 2026-11-20 پس از مشاهده نمونه رابط فرصت‌های فروش، مهاجرت رابط کاربری هم‌ره از Filament به Vue را تأیید کرد.

از این تاریخ، Filament دیگر فناوری هدف برای رابط کاربری جدید نیست. رابط جدید با Vue 3 ساخته می‌شود و Laravel 13، MariaDB و منطق عملیاتی موجود حفظ می‌شوند. این تصمیم صرفاً لایه Presentation را تغییر می‌دهد؛ بازنویسی پروژه، تعویض پایگاه داده یا ساخت سیستم موازی هویت مجاز نیست.

نمونه فعلی `/prototype/opportunities` فقط یک اثبات اولیه Vue با Blade و دریافت JSON است؛ Inertia در آن پیاده‌سازی نشده و این نمونه به‌تنهایی الگوی نهایی معماری یا اثبات آمادگی مهاجرت نیست.

## اصول غیرقابل مذاکره

1. احراز هویت، Session، کاربران، عضویت شرکت، Role و Permission فعلی حفظ می‌شوند.
2. تمام داده‌های عملیاتی همچنان با `company_id` و Company Context معتبر محدود می‌شوند.
3. منطق کسب‌وکار در Action/Service/Domain فعلی باقی می‌ماند؛ Vue محل پیاده‌سازی قواعد دامنه نخواهد بود.
4. API، Page Controller، جست‌وجو، Export، فایل و هر عملیات سرور باید Policy و Permission واقعی را اعمال کنند؛ مخفی‌کردن آیتم منو جایگزین مجوز Backend نیست.
5. رابط فارسی، RTL، اعداد فارسی، تاریخ شمسی و فونت محلی از ابتدا جزو قرارداد هستند.
6. موبایل باید با الگوهای اختصاصی موبایل طراحی شود؛ کوچک‌کردن جدول دسکتاپ معیار پذیرش نیست.
7. استقرار نهایی باید روی هاست اشتراکی ممکن باشد. Node/Vite فقط برای build لازم است و اجرای دائمی Node، SSR یا سرویس جداگانه پیش‌فرض نیست.
8. تا زمان تکمیل و پذیرش جایگزین‌ها، Filament، وابستگی‌ها، Resourceها و مسیر ورود فعلی حذف نمی‌شوند.
9. هیچ داده، Migration یا قابلیت عملیاتی صرفاً به دلیل مهاجرت UI حذف یا بازنویسی نمی‌شود.

## مسیر اجرا

### مرحله 0 — خط مبنا و ممیزی
- فهرست تمام Resourceها، Pages، Widgets، Relation Managers، Actions، Policies و مسیرهای Filament استخراج شود.
- هر قابلیت با مدل، Action/Service، مجوز و تست مرتبط نگاشت شود.
- وضعیت تست‌ها، build و بکاپ قابل بازیابی ثبت شود.
- وابستگی‌هایی که فقط برای Filament استفاده می‌شوند شناسایی شوند؛ هنوز حذف نشوند.

### مرحله 1 — زیرساخت رابط جدید
- پوسته مشترک Vue، Layout دسکتاپ، ناوبری واکنش‌گرا و منوی موبایل.
- سیستم طراحی مرکزی، فونت محلی، RTL، تم روشن/تاریک و اجزای پایه.
- قرارداد درخواست/پاسخ، خطا، اعتبارسنجی، اعلان، صفحه‌بندی و مجوز.
- حفظ مسیر ورود و Session فعلی Laravel.

### مرحله 2 — پایلوت کامل فرصت‌های فروش
- فهرست، جست‌وجو، فیلتر، صفحه‌بندی، مشاهده، ایجاد، ویرایش و عملیات مجاز.
- رعایت دسترسی own/team/company و جداسازی شرکت.
- آزمون دسکتاپ، تبلت و موبایل و مقایسه خروجی با رفتار فعلی.
- تأیید مالک پیش از گسترش الگو به ماژول‌های دیگر.

### مرحله 3 — مهاجرت تدریجی ماژول‌ها
ترتیب هر ماژول بر اساس وابستگی و ریسک تعیین می‌شود. هر ماژول فقط پس از تکمیل پوشش قابلیت‌ها، مجوزها، تست‌ها و پذیرش UI از مسیر قدیمی خارج می‌شود.

### مرحله 4 — حذف کنترل‌شده Filament
فقط پس از اثبات برابری قابلیت‌ها و نبود مصرف‌کننده باقی‌مانده:
- مسیرها و Providerهای Filament حذف شوند.
- پکیج‌ها و assetهای مختص Filament حذف شوند.
- ورود، مجوزها، اعلان‌ها، فایل‌ها، گزارش‌ها و عملیات پس‌زمینه مستقل از Filament آزموده شوند.
- استقرار و rollback روی محیط مشابه هاست اشتراکی آزموده شود.

## دروازه‌های پذیرش

- عدم نشت داده میان شرکت‌ها، با تست منفی cross-company.
- برابری مجوز رابط و Backend برای فهرست، مشاهده، ایجاد، ویرایش، حذف، Export و فایل.
- حفظ تمام عملیات تجاری و تاریخچه‌ها.
- پوشش تست مسیرهای اصلی هر ماژول.
- نبود اسکرول افقی غیرضروری در موبایل.
- کارکرد build تولیدی بدون Node runtime.
- امکان بازگشت به نسخه قبلی تا پیش از حذف نهایی Filament.

## مواردی که هنوز تصمیم قطعی ندارند

- انتخاب نهایی الگوی اتصال Vue به Laravel (Inertia یا Blade/API) پس از یک ارزیابی فنی محدود و مقایسه پیچیدگی فرم‌ها، اعتبارسنجی، ناوبری و استقرار.
- کتابخانه‌های UI یا فرم؛ تا زمان اثبات نیاز، وابستگی جدید اضافه نمی‌شود.
- زمان دقیق حذف Filament؛ وابسته به تکمیل همه دروازه‌های پذیرش است.

## وضعیت فعلی

- نمونه Vue فرصت‌ها: موجود در شاخه آزمایشی؛ فقط‌خواندنی و فاقد منوی کامل.
- Inertia: در نمونه فعلی استفاده نشده است.
- مهاجرت ماژول‌های عملیاتی: آغاز نشده.
- حذف Filament: انجام نشده.
